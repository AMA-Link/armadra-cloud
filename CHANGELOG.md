The assertion `team` becomes `{ teamId, role: owner|admin|member|billing|guest }`; the relay and tunnel tokens replace `org` with an optional `team` (team id); the `org` claim is reserved for a future enterprise layer. SaaS never launched and the 1.1 department semantics (`lead|member`) and `org` were never issued, so they change in place. - 协议 1.3：端到端通道（协议包 0.4.0，cloud 各包同版本；cloud-api §20；Refs #43）：新子路径 `./e2e` 实现 `armadra-e2e/1`——临时 X25519 + HKDF-SHA256 转录链 + Ed25519 身份签名的三消息握手（core 用现有源钥签转录，客户端用设备钥签，首次可带配对秘密派生的 `proof`），之后两个方向各一把 AES-256-GCM 记录密钥（nonce = 4 字节前缀 + 8 字节计数器，长度字段进 aad，重放、乱序、截断、篡改都失败），r0 `accept`、6 位 SAS、身份指纹与 `pinHint`；可选的 64 字节填充缺省关。原语全部来自 WebCrypto，页面、手机、Node 与 Workers 同一份代码；黄金向量 `fixtures/e2e/handshake.json` 由 `node:crypto` 独立参照实现算出。隧道 `OPEN.kind` 加 `e2e`（只能是 `GET /_relay/e2e`、不带头），源能力 `e2e`（`TUNNEL_CAPABILITIES`），中继令牌加可选声明 `dev`（issuer 侧设备 id，只计数不鉴权）。HTTP/1.1 与 WebSocket 帧的纯编解码从中继内核迁入协议包（`./http1`、`./ws-frames`，不再依赖 `Buffer`），供经通道发请求的页面共用。老源不报 `e2e` 就收不到这种 `OPEN`，明文路径照旧可用。
  Protocol 1.3: end-to-end channel (protocol package 0.4.0, all cloud packages in lockstep; cloud-api §20; Refs #43): the new `./e2e` subpath implements `armadra-e2e/1` — a three-message handshake built from ephemeral X25519, an HKDF-SHA256 transcript chain and Ed25519 identity signatures (core signs the transcript with its existing source key, the client with a device key, optionally adding a `proof` derived from a pairing secret on first contact), followed by one AES-256-GCM record key per direction (nonce = 4-byte prefix + 8-byte counter, the length field is the AAD, so replay, reordering, truncation and tampering all fail), the r0 `accept`, a 6-digit SAS, identity fingerprints and `pinHint`; optional 64-byte padding is off by default. Every primitive comes from WebCrypto, so web, mobile, Node and Workers share one implementation; the golden vectors in `fixtures/e2e/handshake.json` are computed by an independent `node:crypto` reference. Tunnel `OPEN.kind` gains `e2e` (only `GET /_relay/e2e` with no headers), sources advertise the `e2e` capability (`TUNNEL_CAPABILITIES`), and relay tokens gain an optional `dev` claim (issuer-side device id, counted but never used for authorization). The pure HTTP/1.1 and WebSocket frame codecs move from the relay kernel into the protocol package (`./http1`, `./ws-frames`, no longer relying on `Buffer`) so web clients sending requests through the channel can share them. Sources that do not advertise `e2e` never receive such an `OPEN`, and the plaintext path keeps working.

  Media tickets (cloud-api §12): a client holding a relay token calls `POST <source>/_relay/media-tickets` for a ticket, and the browser fetches `<source>/_relay/m/<ticket>`; the edge forwards GET / HEAD to the path fixed at issue time. Tickets are bound to the source, a single path and the issuing token, expire after 5 idle minutes or 30 minutes in total, and neither the path nor the ticket is logged. `<video src>` on relayed sources now plays directly with `Range`.

### 修复 / Fixed

- 中继与 cloud 的 HTTP 监听空闲 keep-alive 由 Node 缺省 5 秒改为 75 秒（请求头超时 76 秒、整条请求 5 分钟）：iPad / iOS 的 WebKit 复用刚被服务端关掉的连接发 POST 时不重试，偶发「这一轮没有完成」。
  The relay and cloud HTTP listeners keep idle keep-alive connections for 75 s instead of Node's 5 s default (headers timeout 76 s, request timeout 5 min): WebKit on iPad / iOS does not retry a POST on a connection the server has just closed, which occasionally ended an agent turn.

### 变更 / Changed

- 边缘限流缺省额度放宽：CORS 预检按 IP 每分钟 1200（原 300），有效令牌 1200（原 600），同一账号 3600（原 1800），同一账号并发 WebSocket 256（原 64）；中继预检与控制面 `Access-Control-Max-Age` 由 600 改为 7200。
  Relaxed default edge limits: CORS preflights 1200 per IP per minute (was 300), 1200 per relay token (was 600), 3600 per account (was 1800), 256 concurrent WebSockets per account (was 64); `Access-Control-Max-Age` on relay preflights and the control API goes from 600 to 7200.
