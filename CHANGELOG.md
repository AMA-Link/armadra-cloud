## 0.5.0（2026-10-17）

### 新增 / Added

- 中继流量统计（cloud-api §19，Refs #44）：中继按「源 × 账号 / 访客 × 设备（中继令牌 `dev`）× 类别（`e2e` / `http` / `ws` / `media`）× UTC 小时」累计连接数与两个方向的字节，在内存里累加、每 60 秒批量写库（Workers 在攒下新行后 30 秒与检查周期写进各源对象的 DO SQLite），不按帧写库，不记路径、头、IP 与正文。新表 `relay_traffic_buckets`（SQLite 迁移 0002、PostgreSQL 迁移 0003）；`GET /v1/me/traffic`（能力 `me.traffic`，账号本人看全部源、访客只看自己）；`armadra-relay personal traffic` 出表；保留期 `--traffic-retention-days` / `RELAY_TRAFFIC_RETENTION_DAYS`，缺省 90 天，`0` 不记录。状态文件存储只在内存里累计。
  Relay traffic statistics (cloud-api §19, Refs #44): the relay counts connections and bytes in both directions per source × account / guest × device (relay-token `dev`) × kind (`e2e` / `http` / `ws` / `media`) × UTC hour, accumulated in memory and upserted in batches every 60 s (Workers write into each source object's DO SQLite 30 s after new rows appear and on every check cycle) — never per frame, and without paths, headers, IPs or bodies. New table `relay_traffic_buckets` (SQLite migration 0002, PostgreSQL migration 0003); `GET /v1/me/traffic` (capability `me.traffic`; the account sees every source, guests only themselves); `armadra-relay personal traffic` prints a table; retention `--traffic-retention-days` / `RELAY_TRAFFIC_RETENTION_DAYS`, default 90 days, `0` disables recording. The state-file store keeps the counters in memory only.
- 访客链接的身份指纹（cloud-api §20，Refs #43）：`links.accept` 的答案多可选的 `identityFp`，是源登记公钥（端到端通道的身份）的指纹；只作提示，访客按 core 生成的链接片段第三段钉扎。
  Guest-link identity fingerprint (cloud-api §20, Refs #43): `links.accept` answers an optional `identityFp`, the fingerprint of the source's registered key (its end-to-end channel identity); a hint only, guests pin on the third fragment segment the core puts into the link.

### 移除 / Removed

- 中继只转端到端通道（cloud-api §7、§12、§20，Refs #43）：源地址上的明文应用请求（HTTP 与普通 WebSocket 经中继转进隧道、`Armadra-Relay-Token` 头、CORS 预检）与媒体票（`/_relay/media-tickets`、`/_relay/m/<票>`）删除，一律 `404 not_found`、不进隧道；唯一的入口是 `_relay/e2e`。Node 与 Workers 中继都删去 HTTP 转发、明文 WS 桥与媒体票（Workers 唤醒时把 0.5.0 之前留下的明文 WS 桥以 4404 关掉）；内核的 `edge/forward.ts`、`edge/media-tickets.ts` 一并删除。`--limit-preflight` 仍接受但不再使用。要配 Armadra 0.6.0 起的客户端与 core。
  The relay only forwards end-to-end channels (cloud-api §7, §12, §20, Refs #43): plaintext application traffic on source addresses (HTTP and plain WebSockets forwarded into the tunnel, the `Armadra-Relay-Token` header, CORS preflights) and media tickets (`/_relay/media-tickets`, `/_relay/m/<ticket>`) are gone and answer `404 not_found` without touching the tunnel; `_relay/e2e` is the only entry point. Both the Node and Workers relays drop HTTP forwarding, the plaintext WebSocket bridge and media tickets (Workers closes pre-0.5.0 plaintext bridges with 4404 on wake-up); the kernel's `edge/forward.ts` and `edge/media-tickets.ts` are removed. `--limit-preflight` is still accepted but unused. Requires Armadra 0.6.0 or later clients and cores.

## 0.4.0（2026-10-12）

### 新增 / Added

- 中继边缘的端到端通道 `_relay/e2e`（cloud-api §20，cloud 各包同版本 0.4.0；Refs #43）：saas `wss://<sourceId>.src.<域>/_relay/e2e`、personal `wss://<中继>/s/<sourceId>/_relay/e2e`，只认 WebSocket 升级（普通 HTTP 答 404）。令牌、限流、路由与 §7 相同；要带子协议 `armadra-e2e.1`（缺了 4409），源要在隧道 `hello.capabilities` 报过 `e2e`（没报 4404，原因 `e2e_unsupported`）。中继自己完成升级、开 `OPEN { kind: "e2e", method: "GET", path: "/_relay/e2e", headers: [] }`，此后二进制消息与 `DATA` 原样互转（消息边界不保证），文本消息 4400；源 `END` / `RST` 以 1000 / 4404 结束。Node 中继（`e2e-pipe.ts`，双向背压、定时 ping 与空闲断开）与 Workers 中继（`SourceDO` 的 `E2eBridge`，不经 HTTP 转发，休眠后照样还原）行为相同；隧道记下源的能力并随快照存。签发方的中继令牌带 `dev`（就是断言里的设备 id）。指标多一个 `relay_edge_streams_total{kind}`；通道结束日志只记源、流号、字节数、时长与关闭码。明文路径照旧可用。
  The relay edge's end-to-end channel `_relay/e2e` (cloud-api §20, all cloud packages at 0.4.0; Refs #43): saas `wss://<sourceId>.src.<domain>/_relay/e2e`, personal `wss://<relay>/s/<sourceId>/_relay/e2e`, WebSocket upgrades only (plain HTTP answers 404). Tokens, rate limits and routing work as in §7; clients must offer the `armadra-e2e.1` subprotocol (4409 otherwise), and the source must have advertised `e2e` in the tunnel's `hello.capabilities` (4404 with reason `e2e_unsupported` otherwise). The relay completes the upgrade itself, opens `OPEN { kind: "e2e", method: "GET", path: "/_relay/e2e", headers: [] }`, and from then on binary messages and `DATA` are passed through byte for byte (message boundaries are not preserved); text messages close with 4400, and a source `END` / `RST` closes with 1000 / 4404. The Node relay (`e2e-pipe.ts`, backpressure in both directions, periodic pings and idle timeout) and the Workers relay (`E2eBridge` in `SourceDO`, bypassing HTTP forwarding and restored after hibernation) behave the same; tunnels record the source's capabilities and keep them in snapshots. Issued relay tokens carry `dev` (the assertion's device id). Metrics gain `relay_edge_streams_total{kind}`; the end-of-channel log only records the source, stream id, byte counts, duration and close code. The plaintext path keeps working.
- 协议 1.3：端到端通道（协议包 0.4.0，cloud 各包同版本；cloud-api §20；Refs #43）：新子路径 `./e2e` 实现 `armadra-e2e/1`——临时 X25519 + HKDF-SHA256 转录链 + Ed25519 身份签名的三消息握手（core 用现有源钥签转录，客户端用设备钥签，首次可带配对秘密派生的 `proof`），之后两个方向各一把 AES-256-GCM 记录密钥（nonce = 4 字节前缀 + 8 字节计数器，长度字段进 aad，重放、乱序、截断、篡改都失败），r0 `accept`、6 位 SAS、身份指纹与 `pinHint`；可选的 64 字节填充缺省关。原语全部来自 WebCrypto，页面、手机、Node 与 Workers 同一份代码；黄金向量 `fixtures/e2e/handshake.json` 由 `node:crypto` 独立参照实现算出。隧道 `OPEN.kind` 加 `e2e`（只能是 `GET /_relay/e2e`、不带头），源能力 `e2e`（`TUNNEL_CAPABILITIES`），中继令牌加可选声明 `dev`（issuer 侧设备 id，只计数不鉴权）。HTTP/1.1 与 WebSocket 帧的纯编解码从中继内核迁入协议包（`./http1`、`./ws-frames`，不再依赖 `Buffer`），供经通道发请求的页面共用。老源不报 `e2e` 就收不到这种 `OPEN`，明文路径照旧可用。
  Protocol 1.3: end-to-end channel (protocol package 0.4.0, all cloud packages in lockstep; cloud-api §20; Refs #43): the new `./e2e` subpath implements `armadra-e2e/1` — a three-message handshake built from ephemeral X25519, an HKDF-SHA256 transcript chain and Ed25519 identity signatures (core signs the transcript with its existing source key, the client with a device key, optionally adding a `proof` derived from a pairing secret on first contact), followed by one AES-256-GCM record key per direction (nonce = 4-byte prefix + 8-byte counter, the length field is the AAD, so replay, reordering, truncation and tampering all fail), the r0 `accept`, a 6-digit SAS, identity fingerprints and `pinHint`; optional 64-byte padding is off by default. Every primitive comes from WebCrypto, so web, mobile, Node and Workers share one implementation; the golden vectors in `fixtures/e2e/handshake.json` are computed by an independent `node:crypto` reference. Tunnel `OPEN.kind` gains `e2e` (only `GET /_relay/e2e` with no headers), sources advertise the `e2e` capability (`TUNNEL_CAPABILITIES`), and relay tokens gain an optional `dev` claim (issuer-side device id, counted but never used for authorization). The pure HTTP/1.1 and WebSocket frame codecs move from the relay kernel into the protocol package (`./http1`, `./ws-frames`, no longer relying on `Buffer`) so web clients sending requests through the channel can share them. Sources that do not advertise `e2e` never receive such an `OPEN`, and the plaintext path keeps working.

### 变更 / Changed

- 中继边缘不再按只读中继令牌（`ro`）过滤（cloud 各包同版本 0.3.11，协议仍是 1.2，线上形状不变；Refs Armadra#309）：core 的 RPC 一律 `POST`，原来的只读门只放行安全方法与身份域，只读与会话分享的访客连 `system.hello` 都过不去。现在 `ro` 令牌的所有方法照常转给源，读写只由 core 按授予判定；令牌照旧签 `ro`，协议包的 `isReadOnlyAllowed` 保留但标为弃用。cloud-api §14「只读门」同步。
  The relay edge no longer filters read-only relay tokens (`ro`) (all cloud packages at 0.3.11, protocol still 1.2, wire shapes unchanged; Refs Armadra#309): core RPCs are all `POST`, and the old read-only gate only let safe methods and the identity routes through, so read-only and session-share guests could not even reach `system.hello`.
